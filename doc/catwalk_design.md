## ① 判据更正：`lat_med ≥ 14.089` 是**判据错误**，不是「达不到就放宽」

**旧门作废。** 它拿了一个**由被修掉的缺陷产生的数**当底线，且与 `satisfy_spacing` 的走廊在数学上不相容：

1. **走廊上限的推导**（`satisfy_spacing`：最近角点到支撑脚中心线的最小垂距 − 支撑脚半宽 ∈ `[2,10]`）。
   足轴与支撑脚平行时，最近角点距 = 中心侧距 − 半宽(1.5)，故
   `中心侧距 − 1.5 − 1.5 ∈ [2,10]` ⇒ **中心侧距 ∈ [5,13]**；足轴倾斜 δ 时半宽投影变为
   `2.5|sinδ| + 1.5|cosδ|`，上限升到 `11.5 + 2.5|sinδ| + 1.5|cosδ|`（δ=45° 时约 14.33，但需足轴斜 45°）。
2. **指标在直道并行步态下恰好等于该侧距**：对同足折线 `u = p[i+1] − p[i−1]`、
   `v = p[i] − p[i−1]`，设落点在支撑脚坐标系的 `(x, y)`、支撑脚下一步转角 δ，
   则 `lateral = |y·cosδ − x·sinδ|`；直道 `δ=0` ⇒ `lateral = y ≤ 13`。
   ⇒ **清洁步态的 `lat_med` 上限 ≈ 13 < 14.089**。（模型验证：合成直道并行步态 lane 半宽 w=13 → lat_med=13.0；
   w=16/20 才过门，但 w≥14 的落足会被走廊拒绝。）
3. **修复前的 14.089 是书账缺陷撑出来的**（实测）：修复前落足点是按「生成脚的支撑」校验、却落到**另一只脚**上，
   因此实际侧距可以越过走廊。在修复前路径（seed 42 / default）上量到支撑脚坐标系侧距
   `|y|` 中位 **14.86**、最大 **28.32**（> 走廊上限 13），指标最大 **22.5**。
   ⇒ 那道门实际是在要求「保留缺陷带来的额外侧距」。
4. 顺带一条反证：朝向平滑取 0.25 时 seed 42/default 的 `lat_med = 14.310`（能过旧门），
   但 `goal_error = 27.13`、`steps = 112`、`lin = 4.03`——旧门确实会被退化步态骗过。

**替换后的门**（Lead 裁决）：`lat_med ≥ 10.0` 且 `lat_med > 7.713`（HEAD = 已修书账、未修猫步）。
依据：走廊 `[5,13]` 的中点 9，≥10 表示步态稳定落在走廊的**上半段**而不是贴着下沿——贴下沿才是猫步的定义特征。
`> 7.713` 只作为「确实比 HEAD 好」的下限。**其余门一律不动。**

## ② 设计不变量（动手前写下，含强制点）

**场景**：`trapla plan` 在一个 1000×3000 地形上从 start 走到 goal，逐步交替落左右脚；
每一步的落点由「候选网格 → 约束过滤 → 选一个」得到，脚朝向与位置一起进入下一步的参考系。

| # | 不变量（可判定） | 违反的症状 | 强制点 |
|---|---|---|---|
| I1 | **侧向分道**：每步落点在前进方向的垂线上落在本脚一侧，`|侧距| ∈ [5,13]`（走廊）且**始终 > 0** | 双足共线 ⇒ `lat_min ≈ 0`、视觉一条线 | `satisfy_spacing`（走廊）+ 本任务 D 的瞄准点偏移 |
| I2 | **参考系稳定**：候选窗口的参考方向不随步向抖动传播（原实现：`support.rz` ← 上一步步向 ← π/12 网格） | 同足步向 ±180° 振荡（T6 实测） | 本任务 B：`walk_update` 提交时朝向按 0.5 插值 |
| I3 | **前进性**：每步把本体中心朝引导点推进（不许停滞/背向） | 直线行军到 tick 耗尽（T6 假通过） | 反直线门 `length/|goal−start| > 1.05` + `goal_error ≤ 1.5×` |
| I4 | **纯几何 golden 冻结**：`satisfy_*`/`cover`/`standable`/`slide` 的判定语义不随步态策略变化 | golden 变红 | `tests/golden/**` 只读；`next()` 保持原语义（B 只改提交路径） |

## ③ 四条路线对比

| 路线 | 改什么参考系 | 预期 | 风险 | 是否采纳 |
|---|---|---|---|---|
| **A 换参考系** | 候选角相对固定参考（引导方位/全局前进方向），而非支撑脚当前朝向 | 消除参考系自转；单侧窗口不再自激 | 需要新参考量（前进方向）并改动 `walk_candidates` 的语义；与 `satisfy_spacing`（仍以支撑脚中心线为准）形成两套参考，可能互相打架 | **不单独采纳**：D 已经在**选点**层面引入了稳定参考（前进方向），比改窗口更小、可逆 |
| **B 解耦 `next()` 朝向** | `rz` 不再无条件 = 步向，按比例插值 | 断掉「步向抖动 → 朝向 → 窗口参考」的正反馈 | **直接改 `next()` 会让 `satisfy_spacing` 的 golden 红 2 个用例**（实测）；必须挪到提交路径 | **采纳**（只改 `walk_update` 提交路径，`next()` 冻结） |
| **C 显式横向间距目标** | 候选**代价**里加横向间距项（参考零调用的 `ideal_walk`） | 直接约束双足间距 | 与 D 的「瞄通道」重叠：D 的瞄准点已经编码了横向目标；再加代价项是无依据的堆叠（且走廊上限仍卡在 13） | 不采纳（D 已覆盖同一目标，且更小） |
| **D 足印分道** | 瞄准点沿**前进方向**（本体中心→引导点）的垂线偏移半个通道宽，左右脚各偏一侧 | 每只脚沿自己那条线走 ⇒ 两条并排轨迹、交叉消失、间距稳定 | 通道半宽是有物理含义的参数，需给敏感性；参考系换成前进方向后仍受走廊上限约束 | **采纳（主推）** |

**为什么推荐 D+B 而不是 A**：A 只修「窗口相对谁」，落点仍由 `find_target` 的「离瞄准点最近」决定，
瞄准点还是引导点本身 ⇒ 两只脚仍会同时收敛到同一条线（这正是 T6 修复后 `lat_med 7.7` 的成因）。
D 直接给每只脚一个**不同的目标点**，是缺的那个横向目标；B 断掉参考系反馈。二者互补、各自可单独度量。

## ④ 实现（最终代码，`crates/trapla-core/src/robot.rs`）

- `LANE_HALF_WIDTH_CM = 13.0`（物理含义：目标双足横向间距的一半；走廊上限即 13，见 §①）。
- `HEADING_SMOOTHING = 0.5`（物理含义：一步最多把足朝向拉向实际步向几成；1.0 = 原行为）。
- `Robot::lane_aim(guide)`：瞄准点 = `guide` 沿「本体中心→guide」的垂线偏移 `±LANE_HALF_WIDTH_CM`
  （`feet[0]`=Left 偏 −y 侧、`feet[1]`=Right 偏 +y 侧，与 `Robot::new` 初始布置一致）。
- `find_path` 循环里 `walk_to(t, self.lane_aim(guide))`。
- `Robot::next_committed()`：`walk_update` 用它提交新脚状态，`rz` 按 `HEADING_SMOOTHING` 插值；
  `Robot::next()` 保持原语义（golden 需要）。
- 实验期的 `TRAPLA_LANE` / `TRAPLA_SMOOTH` 临时开关**已删除**，只留两个常量。

## ⑨ 未验证项与建议

**未验证**
1. 没有实现路线 A（把候选窗口的参考系换成前进方向）与路线 C（代价里加横向项），只做了对比论证；A 是否比 D 更能压 `proper` 未知。
2. `lat_min` 的越界步只做了定位（少数、中段），没有逐例归因到具体机制（走廊边界 / `avoid_feet_cross` / `bfs` 位移）。
3. `avoid_feet_cross` 分支在这套设计下的作用没有单独消融（它每 2 步就可能触发一次，可能正是 `lat_min` 的来源）。

**建议（给后续任务）**
1. 若要把 `lat_min ≥ 3` 与 `proper == 0` 做到 6/6，下一步值得做的是**消融 `avoid_feet_cross`**（T6 诊断已指出它只重排不避让），
   并给 `find_target` 的候选代价加一项**朝向一致性**（直接压 `|Δψ|`），而不是继续调通道宽度。
2. 走廊上限 13 与「两条并排足印带」的视觉愿望存在系统性张力：`lat_med ≥ 13` 需要放宽 `satisfy_spacing` 的区间语义，
   那属于另一个待决项，本任务按裁决不做。
