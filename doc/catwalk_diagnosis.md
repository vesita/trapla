## ① 猫步的几何定义与主判据

### 1.1 三种候选解释的判定

| 候选解释 | 判定 | 依据（数值 + 位置） |
|---|---|---|
| (a) 双足横向间距长期贴下限 2 | **否** | 基线 `separation_lateral_sequence` 中位 10.2–12.6、p10 6.05–9.45（`baseline/catwalk_metrics.json`，实测）。且代码里 `min_foot_separation=2` 并不约束足中心距：`satisfy_spacing`（`src/robot/robot.cpp:193-226`）比较的是「新脚四角到**支撑脚纵向中心线**的最小垂距 − 支撑脚半宽(1.5)」与 `[min−1e-3, max+1e-3]`（218-221），等价于把「最近角点距中心线」夹在 `[3.5, 11.5]`，平行姿态下对应足中心侧距约 `[5, 13]`。`2` 在本实现里连语义都不是「贴 2」（读码推断，已用 `constraints_test` 的 11 个用例数值复刻校验，见 §②.0）。 |
| (b) 左右脚轨迹接近共线/重合 | **局部成立，非主因** | 两足轨道没有整体重合（横向中位 10.2–12.6 ≈ 脚宽 3 的 3–4 倍），但**个别步贴到 ≈0**：横向间距 min = 0.24 / 0.04 / 1.49 / 3.14 / 0.24 / 0.00（6 个用例）；且左右脚折线**严格交叉 3–10 次/run**（`proper_crossings`，合成对照的正常步态 = 0）。 |
| (c) 摆动脚落点在支撑脚正前方（转向角长期 ≈0） | **是主因** | 候选集是绕摆动脚、半径 `active_distance..max_stride`（16..40，步进 2）、角度**相对支撑脚朝向** ±75°（步进 π/12=15°）的极坐标网格（`robot.cpp:673-687`），再经 `position_check`（683）过滤。数值复刻（§②.2）显示：可行 θ 被 `satisfy_spacing` 的侧向走廊压成很窄的一小撮，且**选哪个 θ 与引导方位几乎无关**；当摆动脚自身侧距 d0 ≥ 7.5 时，引导方位 0°–75° 全部选同一个 θ=0（正前方）。 |

### 1.2 「猫步」的可测量定义

**定义（本项目实测形态）**：摆动脚每步的**步向**被支撑脚当前朝向锁在 π/12 的量化网格与 3.5–11.5 的侧向走廊内；
由于新脚的 `rz` 直接被设为该步向（`robot.cpp:643`，`r ≥ active_distance` 恒成立），下一时刻的支撑脚朝向又被上一步步向替换，
结果是「步向 ≈ 支撑脚朝向 ± 15°」的自传递，双脚沿同一条走廊前后推进、并在走廊内反复换边。

三个可测量的量（阈值）：

1. **同足步向摆动 `|Δψ|` 中位数** = 同一只脚相邻两步步向角差的绝对值中位数。
   基线 15.00°–23.76°（6 用例，实测，口径见 §④）；合成正常步态 = 0.00°。
   量级即候选角度分辨率 π/12 = 15°（`robot.cpp:670`）——步向被量化到该网格的直接证据。
2. **左右脚折线严格交叉数 `proper_crossings`**（口径在 `baseline/tools/catwalk_metrics.py`）。
   基线 3–10；合成正常步态 0；合成共线猫步 0。
3. **横向间距最小值**（同基线口径）。基线 0.00–3.14，即个别步两足投影到同一位置附近。

**门槛**：同时满足 `|Δψ| 中位数 < 8°` 与 `proper_crossings == 0` 与 `横向间距 min ≥ 3.0`，才算「不猫步」。

### 1.3 主判据

**主判据 = `proper_crossings`（左右脚折线的严格交叉对数），修后必须 = 0。**

选择理由：① 它是冻结基线里已经算好的量，不需要新埋点；② 它与代码里 `will_feet_cross`（`robot.cpp:578-591`）的语义直接对应，
是「双脚轨迹是否互相穿越」的直接度量；③ 合成对照给出清晰判据：正常步态（两足平行轨道）= 0，基线 = 3–10。

**它单独不充分**（重要）：把两足轨迹压成一条完全共线的线，`proper_crossings` 也会变成 0（合成共线猫步 = 0），
那是更纯粹的猫步。因此主判据必须与 `横向间距 min ≥ 3.0`、`|Δψ| 中位数 < 8°` 同时成立，禁止用「让双足对齐」的方式满足主判据。

## ② 根因链条

### ②.0 先验证我对 `satisfy_spacing` 的读码

`satisfy_spacing`（`robot.cpp:193-226`）的实际语义：

```
satisfy_spacing(new_pos):
  new_foot = next(new_pos)                      # 196；rz 由 643 决定：stride>=16 时=步向，否则继承摆动脚 rz
  half_width = support.shape.width / 2 = 1.5    # 201
  line = SqLine(support.position, support.rz)   # 204 -> geometry.cpp:373-374，过支撑脚、方向=支撑脚朝向的直线
  spacing = min over new_foot.corner() 的距离   # 209-211（四角中离该线最近者）
  spacing = max(0, spacing - half_width)        # 214
  return 2-1e-3 <= spacing <= 10+1e-3           # 218-221
```

数值复刻（Python，逐行照抄 `Foot::corner`、`SqLine::distance`、`next`）对 `constraints_test` 的 11 个用例：
与**测试期望**一致 10/11，唯一不一致正是 `(50,55)`，与基线实测失败 CSV
`baseline/test_logs/spacing_constraint_failures.csv` 的唯一一行（`50,55,expected=0,actual=1`）完全一致。
即该复刻模型复现了**真实二进制的行为（包括它的已知失败）**，可作为后续算式的依据。
（`(50,55)` 的原因：测试构造 `Robot(40,…)` ⇒ `active_distance = 40*0.4 = 16`（`robot.cpp:19`），
`stride = 10 < 16` ⇒ `next()` 不更新 rz，步向继承 0° ⇒ spacing = 3.5−1.5 = 2.0 ≥ 1.999 通过。）

### ②.1 链条（每环带位置）

1. **引导点**：`guide = direction_determine(position(), guides, true)`（`robot.cpp:367`）。
   注意 `at` 形参未被使用（`src/aStar/direction.cpp:3-19`），返回值是剩余引导点的加权质心（权重在 `direction.cpp:12-18`、`21-26`）。
   ⇒ 引导点是一个**远方的点**，且权重偏向最近的那个引导点。
2. **候选生成**：`walk_candidates()`（`robot.cpp:661-689`）——绕**摆动脚当前位置**、半径 16..40 步进 2（673）、
   角度 = `support_foot.rz + angle_offset`，`angle_offset ∈ [-75°, +75°]` 步进 15°（670、674-676）。
   左右脚**没有任何角度偏向**（与 `biased_walk_candidates` 的唯一差别）。
3. **候选过滤**：`position_check`（`robot.cpp:237-239`）= `satisfy_spacing && satisfy_stride && satisfy_turn`。
   ⇒ `min_foot_separation` **确实进入了候选过滤**（经 683 行），但作为**侧向走廊**（见 §②.0），不是双足间距。
   两个附带细节：`satisfy_stride` 是严格 `<`（229），而扫描循环是 `<=`（673）⇒ `r=40.0` 这一环基本恒被拒（读码推断）；
   `satisfy_turn`（232-235）不做角度归一化，`support.rz` 接近 ±π 时可能误拒（读码推断，未构造实例）。
4. **选择规则**：`find_target`（`robot.cpp:321-331`）按「到引导点的距离」排序取 `candidates[0]`（330）。
   比较器（324-328）里 `support_foot`/`sp` 是死变量。
   关键推论（读码推断 + 数值复刻）：候选点距离 ∈ [16,40]，当引导点距离 ≫ 40 时，
   「离引导点最近」≈「取最大半径那一环 + 角度最接近引导方位」。数值复刻（support 原点 rz=0，swing 侧距 d0）：

   | d0 | 引导方位 0° | 15° | 30° | 45° | 60° | 75° |
   |---|---|---|---|---|---|---|
   | 0.0 | +15°(r=38) | +15° | +15° | +15° | +15° | +30°(r=28) |
   | 2.5 | −15°(r=38) | +15° | +15° | +15° | +15° | +15° |
   | 5.0 | 0°(r=38) | 0° | 0° | +15°(r=32) | +15° | +15° |
   | 7.5 | 0°(r=38) | 0° | 0° | 0° | 0° | +15°(r=22) |
   | 10.0 | 0°(r=38) | 0° | 0° | 0° | 0° | 0° |
   | 12.5 | 0°(r=38) | 0° | 0° | 0° | 0° | 0° |

   ⇒ **引导方位从 0° 到 75°，选出的 θ 几乎不变**；θ 由摆动脚自身侧距 d0 决定，而不是由目标方向决定。
   这就是「为什么结果偏向正前方而不是保持横向间距」：候选集里**没有任何一项以绝对/全局横向间距为目标**，
   唯一的横向约束是以**支撑脚自身朝向**为基准的走廊；支撑脚朝向每步又被上一步步向替换（第 6 环），走廊跟着一起转，
   横向偏移在相邻两步之间自相抵消，不会累积成稳定的双足间距。
   反例（算式）：support 在原点 rz=0、swing 在 (0,10)、r=32 时可行 θ 集数值上仅 `{−45°, 0°}`；引导方位 45° 时仍取 `θ=0, r=38`。
5. **落点提交**：`walk_to`（267-271）= `bfs(get_target(guide))`。`bfs`（430-464）对目标再查一次 `position_check`（452），
   不满足就沿 `rot_neighbour`（419-428，半径 `about_R=(5+3)/4=2.0`）做一次 100 步 BFS；
   兜底返回 `sw.position`（463，此时**返回值不满足 position_check**）。
   ⇒ 落点不一定落在 2.0/15° 网格上；基线 `walk_test` 的失败正是这一类（§⑤）。
6. **朝向传递**：`next()`（`robot.cpp:635-646`）在 `stride >= active_distance(16)` 时把新脚 `rz` 设为**它自己的步向**（643）。
   候选半径恒 ≥ 16 ⇒ 该分支恒成立 ⇒ 脚朝向 = 上一步一步向。
7. **书账错位（读码推断，已由探针实测确认）**：候选在 `robot.cpp:385` 用**当时的**摆动脚生成，
   但目标要到下一轮 `walk_update`（401 / 412）才落到**已经换过脚的**摆动脚上：
   `walk_update`（29-33）内翻一次脚，循环末尾 `robot.cpp:406` 再翻一次 ⇒ 生成脚与落足脚相反。
   逐行复刻主循环（平地 + 45° 引导梯）得到：无偏时 **46/46 次非 avoid 应用都是「为另一只脚生成的候选」**，
   且复刻的前两个落点与脚身份与探针完全一致：
   `baseline/catwalk_foot_probe.txt` 第 0 点 `(33.4096,11.7822) foot=0`；
   该点恰好 = `feet[1]` 初始位置 `(2.5,3.5)` + `32∠15°`（`robot.cpp:25`、初始 rz=0），r=32.000、θ=15.000 都在网格上，
   而围绕 `feet[0]`（`(2.5,−1.7)`，`robot.cpp:22-24`）算出来是 r=33.72、θ=23.56°，两者都不在网格上。
8. **防交叉机制不防交叉**：`will_feet_cross`（578-591）比较的两条线段分别由**两次不同迭代、不同摆动脚状态**生成的候选组成；
   它调用 `segments_intersect`（`src/utils/geometry.cpp:1242-1259`），其中 `cross1*cross2 <= 0` 把**共线/端点接触也算相交**（读码推断）。
   `avoid_feet_cross`（593-608）并不改变落点，只是**交换两步的执行顺序**，并用交换后的状态重算第二个目标。
   实测：探针在 25 组未崩溃运行里命中 2–25 次（`baseline/catwalk_parity_scan.txt`；seed 3 + (500,500) = 8 次 / 25 次 apply）。
   ⇒ 它按设计只会重排，不会消除轨迹交叉，`proper_crossings` 仍为 3–10。

## ③ `biased_walk_candidates` 的作用机制与充分性

### 3.1 逐项对比

| 项 | `walk_candidates`（661-689） | `biased_walk_candidates`（701-740） |
|---|---|---|
| 半径网格 | 16..40 步进 2（673） | 同（725） |
| 角度起点 | `-max_turn`（674） | 左脚 `-max_turn`；右脚 `-10°`（716-722） |
| 角度终点 | `+max_turn`（674） | 左脚 `+10°`；右脚 `+max_turn` |
| 角度步进 | π/12（670） | 同（710） |
| **实际角度序列** | −75,−60,…,−15,0,+15,…,+75 | 左脚：−75,−60,…,0,**+10**；右脚：**−10**,+5,+20,…,+75 |
| 过滤 | `position_check`（683） | 同（735） |

⇒ 两处实质差别：① 角度窗口被单侧截断（左脚禁止 > +10°，右脚禁止 < −10°）；
② 网格相位被改变——偏置后左脚最后一点是 +10°、右脚第一点是 −10°，都**不是 15° 的整数倍**。

数值复刻（同 §②.1 的表，swing 取左/右脚）：

- d0=0、swing=Left：无偏取 `+15°`，偏置取 `−15°`（固定一侧）。
- d0=0、swing=Right：无偏取 `+15°`，偏置取 `−10°`（引导方位 0°）/`+20°`（15°–75°）。
- d0=5 或 10、swing=Left：无偏/偏置都取 `0°`；swing=Right 偏置取 `+5°`。

⇒ 「偏向」确实把「±15° 交替」变成**单侧承诺**，这是它理论上能修猫步的机制。

### 3.2 是否单独就足够：**否**，三条独立理由

**(1) 候选集可能为空 → `candidates[0]` 越界。** `find_target`（330）直接 `return candidates[0];`，没有空集分支（`robot.cpp:321-331`）。
数值扫描（support 原点 rz=0）给出空集姿态族：

| swing 侧距 d0 | −14 | −10 | −6 | 0 | +6 | +10 | +14 |
|---|---|---|---|---|---|---|---|
| 无偏候选数 | 23 | 31 | 39–40 | 40 | 37 | 27 | 19–21 |
| **biasedL 候选数** | **0** | **0** | 19–20 | 20 | 29 | 27 | 19–21 |
| **biasedR 候选数** | 28 | 28–29 | 31 | 23 | 16 | 17 | 13 |

即「摆动脚在支撑脚一侧 10 以上、而窗口只允许向另一侧迈」时，偏置候选集为空。逐行复刻主循环在偏置模式下
于路径第 3 个点即命中空集（`unbiased` 模式同一输入正常走完）。C++ 里这等价于对空 `std::vector` 取 `operator[]`，属未定义行为。
⇒ 接线时必须同时给 `find_target` 加空集分支（回退 `little_step` / 当前位姿 / 无偏窗口）。

**(2) 主循环书账错位使左右偏置落到相反的脚上。** 见 §②.1 第 7 环：候选为脚 X 生成、却落到脚 Y 上（复刻 46/46 确认）。
偏置窗口按 `now_which_foot_to_move` 取（`robot.cpp:716`），即按**生成时刻的摆动脚**取；
若生成脚 ≠ 落足脚，则「左脚的 −75..+10」实际约束的是右脚，反之亦然。
⇒ 必须同时修 `change_feet` 的调用次数/位置，或把「候选 + 生成它的脚」一起缓存到 `pend_dots`。

**(3) 走廊没变，步向仍被支撑脚朝向锁住。** 数值复刻里 d0 ≥ 5 时偏置版仍取 `θ=0`（左脚）/`+5°`（右脚），
即依旧「朝支撑脚正前方迈」。要把引导方向真正拉出来，需要 `guide_bias`（`robot.cpp:475-482`：按 `central_angle(dot) ± π/2`、
半径 `active_distance` 把引导点推到本脚一侧）或 `arc_guide`（484-567：引导点不在本脚一侧时按切线/三等分圆弧重设引导点），
以及 `ideal_walk`（72-132，按 `[min_foot_separation, max_foot_separation]` 与步长直接构造理想落足区）一类「以间距为目标」的机制——
这些当前**全部零调用**（`grep` 结果：仅声明与定义，无调用点）。

### 3.3 可证伪的预测

- **只接 `biased_walk_candidates`（并加空集回退）**：预测 `proper_crossings` 从 3–10 降到 ≤1（两足不再反复换边），
  但同足 `|Δψ|` 中位数**不一定**降到 < 8°（θ 仍被夹在 0/+5），且可能因为书账错位而落到反脚、效果反向。
- **接 biased + `guide_bias` + 修书账**：预测 `proper_crossings = 0`、同足 `|Δψ|` 中位数 < 8°、横向间距 min ≥ 3.0。
- 若哪一条不成立 ⇒ 我关于「侧向走廊 + 朝向传递是主因」的判断被证伪。

## ④ 判据表

新增指标定义（唯一事实源写在这里；其余口径见 `baseline/tools/catwalk_metrics.py` docstring）：

> **同足步向摆动 `|Δψ|`**：按奇偶分足（`index 偶数 = feet[0]`，探针实测严格交替，`baseline/catwalk_parity_scan.txt`），
> 对每只脚把相邻落点连成步向量，取相邻两步向量的夹角差 `Δψ = wrap(ψ[i+1] − ψ[i])`（度），
> 统计 `|Δψ|` 的中位数与 p90。实现时可直接复用 `baseline/tools/catwalk_metrics.py` 的 `read_points` 与分足规则。

| 指标 | 修前（基线实测） | 修后预期 | 主/辅 |
|---|---|---|---|
| `proper_crossings`（左右脚折线严格交叉对数） | 3–10（6 用例：4,10,5,3,4,10） | **= 0** | **主** |
| 同足步向摆动 `|Δψ|` 中位数 | 15.00–23.76°（= π/12 量级） | < 8° | 辅（防退化） |
| 横向间距 min | 0.00–3.14 | ≥ 3.0（≈ 一个脚宽） | 辅（防退化） |
| 横向间距中位数 | 10.20–12.62 | 维持 [5, 13]，相对变化 ≤ ±20% | 辅 |
| 横向间距 p10 | 6.05–9.45 | ≥ 5.0 | 辅 |
| `will_feet_cross` 命中次数/run | 2–25（seed3 default 8/25 次 apply，alt 14） | ≤ 2 | 辅 |
| 步数 `n_points` / 总长 `total_length` | 50–140 / 1090–2906 | 不增加超过 10%（直线度提高应减少） | 辅 |
| `will_feet_cross` 计数与 `proper_crossings` 的一致性 | 前者 2–25，后者 3–10，不相关 | 两者同时趋 0 | 辅（机制有效性） |
| `spacing_violations_2_10` | 45–129 | **不得作为判据** | 不适用 |
| `goal_error` | 17.11–698.43 | 不显著变化（本次不修终到性） | 观察项 |

`spacing_violations_2_10` 不可作判据的理由：`baseline/tools/catwalk_metrics.py` 自己注明它是「足中心距代理」，
与 C++ 的 `satisfy_spacing` 几何定义不同；基线本就不为 0，修好后也不应期望为 0。

合成对照（同一套口径，用来给阈值立据）：正常步态（两足 `y=±5`、步长 30）→ `proper_crossings=0`、`|Δψ|中位=0`、横向间距恒 10；
纯共线猫步（两足 `y=0`）→ `proper_crossings=0`、横向间距 0（说明主判据需要横向间距 min 兜底）；
每两步换边（`y=±5` 交替）→ `proper_crossings=18`、`|Δψ|中位=36.87°`。

## ⑤ 风险与副作用（未标注「实测」的均为 `预测`）

- **`constraints_test`**：只直接调用 `satisfy_spacing/satisfy_stride/satisfy_turn` 与固定输入（`tests/constraints_test.cpp:38`），
  与 `walk_candidates` 的窗口无关。预测接线偏置机制**不改变**其结果（仍只失败 `(50,55)`：expected=0 actual=1，
  `baseline/test_logs/spacing_constraint_failures.csv`，实测）。但若顺手改了 `satisfy_*` 的语义或 `active_distance`，
  会破坏当前通过的 10 个用例——task-1 的函数级 golden（`satisfy_spacing` 等）就是这条防线，必须保持不变。
- **`walk_test`**：基线**已经失败**，`error_type=2` = 「结果点不满足 `position_check`」
  （`baseline/test_logs/walk_with_guide_failures.csv`，实测）——来自 `walk_to` 的 BFS 兜底（`robot.cpp:463`）或无解。
  预测：接线偏置后候选集更小，失败形态可能从「约束不满足」变成**更早触发兜底甚至崩溃**；
  判据应改为「返回值要么满足 `position_check`，要么等于调用前的摆动脚位置」，而不是「必须通过约束」。
- **崩溃风险（高，预测有复现支撑）**：`find_target` 的 `candidates[0]` 无空集保护（`robot.cpp:330`），
  偏置窗口存在空集姿态族（§3.2 表）；此外基线本身 8/40 组合 `exit=134`
  （`baseline/catwalk_parity_scan.txt` 与 `baseline/frozen/crash_evidence.txt`）。接线前先修空集分支。
- **步数/路径长度**：预测 `total_length` 不增；若偏置的网格相位改变导致绕行，可能 +10% 以内。
- **`will_feet_cross` 命中数**：预测从 2–25 降到 ≤2。若仍高，说明真正的问题在
  `avoid_feet_cross` 的「重排而非避让」语义（`robot.cpp:593-608`）与 `segments_intersect` 把共线当相交（`geometry.cpp:1258`），
  而不是窗口偏置。
- **终到性**：预测本任务不触碰 `tick`（`robot.cpp:364`）与 `reach_target`，`goal_error` 不显著变化。

## ⑥ 未验证项

1. **真实地形下偏置窗口是否真的取到空集**：空集姿态族来自解析扫描 + 平地 45° 引导梯的逐行复刻；
   真实 A* 引导→地形下的落点与姿态未跑（只读、禁编译），落地前需用 T0 的探针跑一遍。
2. **引导点序列的精确影响**：`scale_star`（`src/aStar/aStar.cpp:78-137`）带随机源，
   `direction_determine` 的权重（`direction.cpp:12-26`）与 `restore_dot`/`scale` 的双语义未逐位复刻；
   我的复刻只在前两个落点与探针吻合，第 3 点起因地形引导不同而分叉。
3. **`will_feet_cross` 每次触发的落点影响**：只有命中计数（2–25），没有逐次触发的落点序列，
   无法量化 avoid 分支对最终轨迹的贡献。
4. **8/40 组合 `exit=134` 的根因**：未复现、未读 core；与 `candidates[0]` 空集是否同源未验证。
5. **`satisfy_turn` 的 ±π 归一化缺失**（`robot.cpp:232-235`）：读码推断的误拒风险，未构造实例。
6. **`r=40.0` 那一环是否完全不产生候选**（`satisfy_stride` 严格 `<` vs 循环 `<=`）：纯算术推断，未在真实 run 中确认。
7. **「主判据」在口径上的自足性**：`proper_crossings` 用的是 `segments_intersect` 式的端点/共线计数，
   与「视觉上的猫步」之间只做了合成对照校准（正常/共线/换边三种），未做人工看图核对。
